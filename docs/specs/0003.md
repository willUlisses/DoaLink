# Spec 0003: Validade do link de recuperação de senha

## Visão geral
Esta especificação define o comportamento do token utilizado no fluxo de recuperação de senha. O token deve ser gerado como um hash único, enviado ao e‑mail do usuário e ter validade limitada.

## Requisitos funcionais
- **RF-003‑A** — O token deve ser válido por **10 minutos** a partir da geração.
- **RF-003‑B** — Após a primeira utilização ou após a expiração, o token deve ser invalidado e não pode ser reutilizado.
- **RF-003‑C** — O token deve ser armazenado de forma segura (hash) e associado ao usuário que solicitou a recuperação.

## Fluxo de recuperação
1. Usuário solicita recuperação informando o e‑mail.
2. Sistema gera um token (`UUID` -> hash) e armazena com timestamp.
3. Sistema envia um link `https://doalink.example.com/recover?token=<hash>` ao e‑mail.
4. Ao acessar o link, o backend verifica:
   - Existência do token.
   - Se o timestamp está dentro do intervalo de 10 minutos.
   - Se o token ainda não foi utilizado.
5. Caso válido, o usuário pode definir nova senha e o token é marcado como usado.
6. Caso inválido/expirado, o usuário recebe mensagem de erro genérica.

## Considerações de segurança
- O token nunca é armazenado em texto puro; salva‑se apenas o hash.
- O link contém apenas o hash; não há informações sensíveis adicionais.
- O prazo de 10 minutos garante segurança contra interceptação prolongada.
